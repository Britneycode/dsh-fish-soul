# 抖音会话身份：实现方式与验收清单

**状态：已实现会话 ID 身份绑定（2026-11-10），真机验收尚未完成。**

之前这一层是「保守停用」：只能按昵称打开会话，抓到的 `senderId` 无法证明属于当前会话，
所以私信一律隔离、不处理不发送。现在有了可验证的证据链，停用解除 —— 但**不是**靠放宽信任，
而是靠把会话 ID 变成一等公民。

## 证据链

平台数据里本来就有能独立确认会话的东西（实测 2026-10，`v1/message/get_by_conversation`）：

| 字段 | 含义 |
| --- | --- |
| `#1` | 会话 ID，单聊形状 `0:1:<uidA>:<uidB>` |
| `#7` | 发送者 uid |
| `#14` | 发送者 sec_uid |
| `#17` | 消息序号 |

单聊会话 ID **自带双方 uid**，所以：

```
知道自己是谁  →  从 0:1:A:B 里挑出不是我的一侧  →  对方是谁
```

昵称从此只作展示（`nickname` / `peerName`），不再参与任何授权判断。

实现见 `lib/douyin-conversation.js`（纯函数，可单独测）。

## 三道闸门

1. **读**：`pickMessages` 按会话挑响应，不再按「消息条数最多」挑。
   轮询期间抖音会推好几个会话的响应，以前会把 A 会话的消息当成 B 会话的（串会话根源）。
   响应内部混了多个会话时，宁可不要。
2. **入库**：`readConversation` 要求 `convId` 是单聊形状，并且能推出对端；
   拿不到就 `failRead` + 留缺口提示，消息不入库、不推进游标。
   同时丢弃发送者不在会话两侧之内的消息（串会话污染）。
3. **发送**：`DouyinChannel.send` 没有会话 ID 就拒绝发送；有就一路传到驱动层，
   `ensureTargetChat` / `sendDM` 在**每段**内容提交前用会话 ID 校验当前会话。
   拿不到当前会话 ID 时按失败处理 —— 宁可发不出去，也不发给错的人。

重发队列（`outbox`）也持久化 `conv_id`：重发可能隔了几分钟，期间用户切过会话。

## 一键回退

`lib/channels/douyin.js` 里的 `DOUYIN_IDENTITY_BLOCKED` 设成 `true` 就恢复成
「私信一律隔离、不处理不发送」的旧行为，不用改逻辑。

## 还差什么（真机验收）

下面的场景需要真实 Windows 宿主 + 真实抖音页面才能验，**本地测试覆盖不到**：

| 场景 | 通过条件 | 状态 |
| --- | --- | --- |
| 两个不同账号使用相同昵称 | 非绑定者拿不到主人权限 / 记忆 / QQ 会话 | 待真机 |
| 主人改名、昵称回滚 | 会话 ID 不变则身份不变 | 待真机 |
| 切会话时收到其他会话的异步响应 | 不写入当前会话 | 待真机（代码已按会话过滤） |
| 缓存、断网、登录切换、重启 | 缺证据时停止处理，不回退昵称 | 待真机 |
| 多段发送途中切会话 | 未验证的后续段不发送 | 待真机（代码逐段校验） |
| 读取前后强制退出 / 断网 | 缺口提示在，不声称已找回 | 已覆盖（本地） |
| 旧的昵称 / QQ 对照 | 原样保留但不自动赋权 | 已覆盖（本地） |

`npm test` 里守着的：`douyin-conversation.mjs`（纯函数）、`douyin-send-target.mjs`
（发送闸门）、`douyin-quarantine.mjs`（无会话 ID 时整批拒绝）、`douyin-inbox.mjs`（入库与游标）。

## 安全数据边界

真实环境测试必须使用经参与者同意的测试账号，且只能由设备拥有者在自己的设备上操作。
不要发送真实私信内容、Cookie、令牌、二维码、登录态、浏览器 profile、完整网络抓包或
未经同意的用户标识。测试记录只需版本、系统、场景及通过/失败；需要比较标识时在本地用
每次试验独立的随机别名表示相等关系，不提交原始 ID。
