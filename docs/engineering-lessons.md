# 工程经验与 PR 准入

## 合并前必须确认

- 先界定信任边界：QQ / B站 / 抖音消息、模型输出、导入文件、远端响应均是不可信输入。明确它们能触及的本地路径、网络、凭据和外部发送动作；默认最小权限。
- 不应合并：越过授权或白名单读取/外发数据；将密钥、聊天或本地文件发送到未说明且未经授权的目标；引入无法解释的安装脚本、混淆代码或可疑依赖；不安全默认开启对外发言或删除数据；绕过安全检查而没有明确迁移方案和测试。发现异常时先保留证据、隔离核查，不以作者身份或自动化结果推断动机。
- 路径白名单不能只用字符串前缀或 `resolve`：对根目录和目标做真实路径检查，测试文件及目录符号链接 / Windows junction、相邻前缀、目录和不存在的路径；还要考虑检查与读取之间的竞态。
- 网络下载上限必须在流式读取时检查实际字节，不仅依赖 `Content-Length`、附件声明大小或读完再判断。测试无长度、虚报长度、分块、边界值、超限中止及下载失败；图片、语音、文件分别检查，不能假设一处修复覆盖所有入口。
- 不要把 HTTP URL 视为安全：明确 URL 来源、协议、重定向、DNS/内网地址、代理兼容性与访问凭据，针对 SSRF 建立端到端防护和测试；单纯校验字符串或首次 DNS 不足以证明安全。
- 不要为通过 CI 删除或弱化断言、静默跳过测试、捕获异常后报成功。每个行为变化需有正常、失败、边界和回归用例；需要真实宿主、浏览器或平台的功能，明确标注模拟与真实验证的区别、未覆盖的平台及原因。
- 按功能拆分 PR，说明来源、依赖、配置默认值、兼容性、迁移、回滚和验证；涉及发版、凭据、数据库、自动发送时独立审查。禁止把 CI 绿色当作安全审计完成。
- 自动发版须测试每一步中断及重跑（tag、Release、npm 发布、latest/gitHead 验证），不可把“tag 存在”当作整个发布链已完成；不要为了补发覆盖现有版本或把异常当成功。
